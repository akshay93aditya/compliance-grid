# Seed CKG (demo only)

This directory contains a snapshot of extracted obligations from the Karnataka labour pilot. **It is loaded only on opt-in via `npm run db:demo`** — `npm run db:setup` creates schemas with an empty CKG by default.

```
seed/<jurisdiction>/<domain>/instruments.jsonl
                            /sources.jsonl
                            /obligations.jsonl
```

One JSON object per line. Field order matches the canonical Zod schemas in `src/schemas/`.

## Loading the seed (opt-in)

```bash
npm run db:setup        # migrations only — empty CKG
npm run db:demo         # opt-in: migrate + load the IN-KA labour pilot
                        # (every obligation tagged extracted_by='demo')
npm run db:demo:clear   # remove demo data + orphan parent rows
```

`db:demo` is idempotent — re-running inserts only rows the local DB doesn't already have (`ON CONFLICT DO NOTHING` on the canonical key).

**The demo CKG is clearly badged** on `/health` and `/obligations` with an amber banner. It is not — and is not pretending to be — a complete picture of compliance for any real entity, even one matching the pilot profile (IN-KA pvt-ltd manufacturing). It's there so the engine has something non-trivial to evaluate against. Real obligations come from running discovery against the Source Index regulators that apply to your profile.

## Refreshing the seed

Maintainers refresh the seed periodically from a known-clean CKG:

```bash
npm run db:seed:export
```

This dumps the current `instruments`, `sources`, and `obligations` tables to JSONL, partitioned by jurisdiction + domain. Test-leaked rows (URLs containing `test.example`, `localhost`, `127.0.0.1`) are filtered.

The export does **not** include `change_events` (those are detection-time records, regenerated by the patrol loop in any deployment) and does **not** touch the Org Vault.

## What this seed contains

The pilot's IN-KA labour extraction:
- 12 instruments referenced by at least one obligation
- 20 sources (real karmika PDFs)
- 163 obligations (auto-committed at confidence >= 0.9 per D9)

Orphan instruments (registered but with no obligations attached) are not exported — they contribute nothing to a downstream operator's CKG.
